Trajectory viewers

Three views of the same benchmark. The founder pipeline builds an app; the crowd pipeline decides whether anyone would use it; the rubric track grades that same app against what its brief actually asked for. The first two replay over time, so you can watch what happened rather than read what was logged. The third is a verdict you can audit line by line.

Founder trajectory viewer

Replay any build by id: every turn, tool call, file edit and browser action on a scrubbable timeline.

  • All three run structures — single agent, 4-agent local, dynamic orchestrator
  • Swimlane per specialist, with the session ids that prove each one resumes its own memory
  • Dynamic mode gets a spawn gantt showing subagents genuinely running in parallel
  • Chain of thought, prompts, patches and subagent sessions — everything the session store keeps
  • Rendered diffs, Playwright page states, accessibility snapshots and screenshots
  • Download the whole trajectory as one JSON, or the raw artifacts as a zip

Crowd trajectory viewer

Replay any crowd simulation: the social graph forming, the launch post spreading, and each agent's hands-on trial of the app.

  • Social architecture — a live follow graph that lights up as agents post, repost, quote and comment
  • Timeline playback over the simulation clock, round by round
  • Per-agent feed, verdict, and the agent's own recorded reasoning
  • App-trial replay — every click and keystroke, with the real screenshots
  • Run the app yourself, side by side with the replay

Rubric grade viewer

The second scoring track: the same app graded against its brief, item by item, with the evidence for every verdict.

  • Every item, every tier — what was claimed, what was observed, and which of the two the score used
  • Decided by code or by the model, labelled — most points never pass through a model at all
  • The arithmetic, shown — base, penalties, the −25 cap, and why a gate failure means 0
  • Per-pass verdicts, so an item the three passes disagreed on says so
  • Side by side with the ViralScore, which is the whole reason this track exists
  • The grader's own tool log, so a verdict can be checked rather than believed
On thinking traces. Founder builds now record the model's actual chain of thought, read from opencode's session store — along with the prompts we sent it, every subagent it delegated to, and the file patches it wrote, none of which ever reached the stdout transcript. The founder viewer shows all four, and distinguishes a thought the provider encrypted from one that was never had. Builds recorded before the capture existed still open, labelled partial trace so a thin record is never mistaken for a quiet model. Crowd agents have always recorded their reasoning, and the crowd viewer shows it verbatim.
